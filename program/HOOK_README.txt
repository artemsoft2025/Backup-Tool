================================================================================
  ХУК ПОСЛЕ СОЗДАНИЯ АРХИВА (post_backup_hook)
================================================================================

Начиная с версии 5.4, backup умеет вызывать внешний скрипт или команду
после каждого успешно созданного архива. Это позволяет автоматически
загружать архив в облако, на SSH-сервер бэкапов или отправлять уведомление —
без правки самого backup.


НАСТРОЙКА
---------

В config.ini, секция [General]:

    # Путь к скрипту ИЛИ команда. Пусто = отключено.
    post_backup_hook = ~/backup_tool/upload_hook.sh
    post_hook_timeout = 600

Параметры:

  post_backup_hook
    Путь к скрипту (.sh, .bat, .ps1, .exe) ИЛИ команда (rclone ..., scp ...,
    curl ...). Пусто = выключено.

  post_hook_timeout
    Таймаут в секундах. Применяется К КАЖДОМУ вызову хука отдельно:
    если архив разбит на тома, хук вызывается для каждого тома, и таймаут
    отсчитывается заново. Если скрипт не успел — он прерывается, но
    бэкап считается успешным.

Поддерживаются ~ (домашняя папка) и относительные пути.


ЧТО ПОЛУЧАЕТ СКРИПТ
-------------------

Аргументы командной строки:

  $1 — полный путь к архиву
       пример: /home/user/backups/docs/full/2026-11-26_full.zip
  $2 — имя профиля
       пример: docs
  $3 — тип бэкапа: full или inc
  $4 — размер архива в байтах
       пример: 1048576

Переменные окружения (доступны всегда):

  BACKUP_FILE    — полный путь к архиву
  BACKUP_PROFILE — имя профиля
  BACKUP_TYPE    — full / inc
  BACKUP_SIZE    — размер в байтах


ДВА РЕЖИМА РАБОТЫ
-----------------

Режим 1: путь к скрипту

Указываете путь к существующему файлу — backup.exe запустит его и передаст
И аргументы, и переменные окружения:

    ; Linux / macOS
    post_backup_hook = ~/backup_tool/upload_hook.sh

    ; Windows
    post_backup_hook = C:\BackupTool\upload_hook.bat
    post_backup_hook = C:\BackupTool\upload_hook.ps1

Скрипт читает данные как удобно — через $1…$4 (Linux) / %1…%4 (Windows)
или через переменные окружения.

Режим 2: командная строка

Указываете команду напрямую — её раскрывает shell, поэтому доступны
ТОЛЬКО переменные окружения (не позиционные аргументы).

ВАЖНО: всегда заключайте $BACKUP_FILE / %BACKUP_FILE% в кавычки —
иначе путь с пробелами (например, C:\Users\My User\...) развалится:

    ; Linux — shell раскрывает $VAR:
    post_backup_hook = rclone copy "$BACKUP_FILE" yandex:Backups/$BACKUP_PROFILE/$BACKUP_TYPE/

    ; Windows — cmd раскрывает %VAR%:
    post_backup_hook = rclone copy "%BACKUP_FILE%" yandex:Backups/%BACKUP_PROFILE%/%BACKUP_TYPE%/

Режим выбирается автоматически: если значение — существующий файл, это
скрипт; иначе — команда.


РАЗДЕЛЕНИЕ НА ТОМА
------------------

Если включено max_volume_size > 0 и архив разбит на несколько томов,
хук вызывается отдельно для каждого тома. В BACKUP_FILE будет путь к
конкретному тому, а $4 / BACKUP_SIZE — размер этого тома.


ПОРЯДОК ВЫПОЛНЕНИЯ
------------------

После создания архива backup.exe делает:

  1. Проверка целостности (verify_archive).
  2. Репликация на носители с меткой ([Replication]), если включена.
  3. Хук post_backup_hook — загрузка в облако / по SSH / уведомление.

То есть хук идёт после локальных копий. Если репликация на флешку не
удалась, хук всё равно запустится.


ПОВЕДЕНИЕ ПРИ ОШИБКЕ
--------------------

  — Хук вернул ненулевой код → backup.exe пишет предупреждение, но
    считает бэкап успешным (архив уже создан локально).
  — Хук превысил post_hook_timeout → он прерывается, пишется
    предупреждение.
  — Вывод скрипта (stdout / stderr) попадает в лог backup.exe.

Хук никогда не ломает сам бэкап — его задача только «докинуть» архив
куда-то ещё.


ТЕСТИРОВАНИЕ БЕЗ БЭКАПА
-----------------------

Проверить, что хук корректно отрабатывает (например, что rclone настроен
и ключи SSH на месте), можно на последнем существующем архиве, не создавая
новый:

    backup.exe --test-hook              # все профили
    backup.exe --test-hook -p docs      # только профиль docs

Команда берёт самый свежий архив профиля и прогоняет его через хук.


ПРИМЕРЫ СКРИПТОВ
----------------

В комплекте (в той же папке, что backup):

  upload_hook.sh  — Linux / macOS — rsync, rclone, scp, Telegram
                    (раскомментировать нужный)
  upload_hook.bat — Windows — сетевой диск, rclone, scp, Telegram

Оба файла по умолчанию делают безопасное локальное копирование в
~/backup-upload/<профиль>/<тип>/ (вариант E) — чтобы можно было сразу
проверить, что хук работает. Для реальной загрузки раскомментируйте
нужный вариант (A–D) и закомментируйте E.


МИНИМАЛЬНЫЙ РАБОЧИЙ ПРИМЕР
--------------------------

config.ini:

    post_backup_hook = ~/backup_tool/upload_hook.sh
    post_hook_timeout = 600

~/backup_tool/upload_hook.sh:

    #!/usr/bin/env bash
    rclone copy "$BACKUP_FILE" "yandex:Backups/$BACKUP_PROFILE/$BACKUP_TYPE/"

После каждого бэкапа архив автоматически уедет в Яндекс.Диск в папку
Backups/<профиль>/<full|inc>/.
