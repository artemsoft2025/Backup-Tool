================================================================================
ПРИМЕР 1. Минимальный — один профиль, только локально
================================================================================
Когда: попробовать; один компьютер, одна папка.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Результат: E:\Backup\default\full\... и E:\Backup\default\inc\...


================================================================================
ПРИМЕР 2. Два профиля (документы + фото), только локально
================================================================================
Когда: хотите отдельные истории для разных типов файлов.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
max_full_backups = 4
max_incremental_backups = 7
max_age_days = 180
compression_level = 6
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = false

[Include]
patterns =
    *.txt
    *.docx
    *.xlsx
    *.pdf
    *.jpg
    *.jpeg
    *.png

[Exclude]
patterns =
    *.tmp
    *.log
    Thumbs.db
    .DS_Store

[Profile:docs]
paths =
    C:\Users\user\Documents
    C:\Users\user\Desktop

[Profile:photos]
paths =
    C:\Users\user\Pictures
--------------------------------------------------------------------------------

Результат: E:\Backup\docs\... и E:\Backup\photos\...
Лимиты (4 полных / 7 инкрементальных) — на КАЖДЫЙ профиль отдельно.


================================================================================
ПРИМЕР 3. Репликация на флешку
================================================================================
Когда: хотите, чтобы копии автоматически падали на флешку.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = true
marker_name = BACKUP_TARGET

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Подготовка флешки (один раз):
    backup.exe --init-target I:\
    backup.exe --list-targets

Догнать существующие архивы на флешку:
    backup.exe --replicate

Результат: при каждом бэкапе архивы копируются в I:\BackupTool\...
Носители без файла BACKUP_TARGET игнорируются.


================================================================================
ПРИМЕР 4. Шифрование архивов
================================================================================
Когда: бэкапы содержат конфиденциальные данные.

ВНИМАНИЕ: для шифрования нужен пакет pyzipper (если собирали бинарник
с --collect-all pyzipper — он уже внутри). Пароль восстановить нельзя!

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

encryption_enabled = true
encryption_password = MyStrongPassword_2026!
# Либо — путь к файлу с паролем (безопаснее, чем в открытом виде):
# encryption_password_file = C:\BackupTool\password.txt

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Проверка пароля:
    backup.exe --restore E:\Backup\default\full\2026-11-27_full.zip --target C:\RestoreTest

ПРИМЕР 5. Репликация + шифрование
================================================================================
Когда: конфиденциальные данные + копия на флешку.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

encryption_enabled = true
encryption_password_file = C:\BackupTool\password.txt

[Replication]
enabled = true
marker_name = BACKUP_TARGET

[Folders]
paths =
    C:\Users\user\Documents
    C:\Users\user\Desktop
--------------------------------------------------------------------------------

На флешке архивы тоже зашифрованы. Для восстановления — тот же пароль.


================================================================================
ПРИМЕР 6. Разбиение на тома (для больших архивов)
================================================================================
Когда: бэкап больше 1-2 ГБ, хотите частями (например, FAT32 — лимит 4 ГБ
на файл).

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

# Тома по 1 ГБ
max_volume_size = 1073741824
volume_prefix = part

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Videos
--------------------------------------------------------------------------------

Результат: вместо 2026-11-27_full.zip появятся
    2026-11-27_full.part001.zip
    2026-11-27_full.part002.zip
    ...

Восстановление — указать первый том:
    backup.exe --restore E:\Backup\default\full\2026-11-27_full.part001.zip --target C:\Restore

ПРИМЕР 7. Бэкап на сетевой диск (NAS)
================================================================================
Когда: есть NAS или расшаренная папка в сети.

--------------------------------------------------------------------------------
[General]
# Windows: UNC-путь
backup_base = \\NAS\backup\MyPC
# Linux: смонтированный путь
# backup_base = /mnt/nas/backup/MyPC

logging_enabled = true
log_file = \\NAS\backup\MyPC\logs\backup.log

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Нужны права на запись в \\NAS\backup\MyPC.
Если NAS отключён — утилита выдаст ошибку, локальные архивы не пострадают
(их просто не будет).


================================================================================
ПРИМЕР 8. Только документы (фильтр Include)
================================================================================
Когда: бэкапить не всё, а только определённые типы файлов.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = false

[Include]
# Белый список — бэкапим ТОЛЬКО эти файлы
patterns =
    *.docx
    *.xlsx
    *.pptx
    *.pdf
    *.txt
    *.odt

[Exclude]
patterns =
    *.tmp
    ~$*              # временные файлы Office
    Thumbs.db

[Folders]
paths =
    C:\Users\user\Documents
    C:\Users\user\Desktop
--------------------------------------------------------------------------------

В архив попадут только docx/xlsx/pptx/pdf/txt/odt. Картинки, видео,
музыка — игнорируются, даже если лежат в тех же папках.

Важно: пустой [Include] = включить ВСЕ файлы (кроме [Exclude]).
Непустой [Include] = включить только совпавшие.

ПРИМЕР 9. Исключить тяжёлые папки (node_modules, .git и т.п.)
================================================================================
Когда: бэкапите папку с проектами, но не тянете служебные каталоги.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = false

[Include]
patterns =

[Exclude]
patterns =
    node_modules
    .git
    .venv
    venv
    __pycache__
    *.pyc
    *.pyo
    .idea
    .vscode
    target
    build
    dist
    *.log
    *.tmp

[Folders]
paths =
    C:\Users\user\Projects
--------------------------------------------------------------------------------

В архиве — исходники, но не зависимости и не артефакты сборки.


================================================================================
ПРИМЕР 10. Ежемесячный полный бэкап
================================================================================
Когда: полный бэкап раз в месяц, инкременты — по необходимости.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
max_full_backups = 12          # храним год полных
max_incremental_backups = 30
max_age_days = 365
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = false

[Schedule]
schedule_mode = monthly
full_backup_day_of_month = 1   # 1-го числа каждого месяца

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

1-го числа каждого месяца — полный бэкап (если есть изменения).
В остальные дни — инкремент или «нет изменений».


================================================================================
ПРИМЕР 11. Агрессивное хранение (много архивов)
================================================================================
Когда: важные данные, места много, готовы хранить долго.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
max_full_backups = 12
max_incremental_backups = 60
max_age_days = 730            # 2 года
verify_archive = true         # проверять каждый архив после создания
compression_level = 9         # максимум (медленнее, но меньше)
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = true
marker_name = BACKUP_TARGET

[Schedule]
schedule_mode = smart

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Минус: медленнее и больше места.
Плюс: максимум истории, дублирование на носитель.


================================================================================
ПРИМЕР 12. Экономное хранение (мало архивов)
================================================================================
Когда: места мало, важна только свежая копия.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
max_full_backups = 2
max_incremental_backups = 3
max_age_days = 30
compression_level = 6
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = false

[Schedule]
schedule_mode = weekly
full_backup_day = 1           # полный по понедельникам

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Не больше 2 полных и 3 инкрементальных. Старше 30 дней — удаляются.


================================================================================
ПРИМЕР 13. Два носителя с метками
================================================================================
Когда: хотите, чтобы копия ложилась на КАЖДЫЙ подключённый носитель
с меткой (две флешки, флешка + внешний HDD).

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

[Replication]
enabled = true
marker_name = BACKUP_TARGET

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Подготовка (один раз для каждого носителя):
    backup.exe --init-target I:\        (первая флешка)
    backup.exe --init-target J:\        (вторая флешка / внешний HDD)

Проверка:
    backup.exe --list-targets
    # 📤 Найдено носителей с меткой: 2
    #   • USB      I:\  свободно: 36.4 GB
    #   • HDD      J:\  свободно: 900.1 GB

При каждом бэкапе архивы копируются на ОБА носителя.
Если один отключён — копия уйдёт только на подключённый (с предупреждением).


================================================================================
ПРИМЕР 14. Разные профили на разные диски (два config.ini)
================================================================================
Когда: docs — на локальный диск, photos — в папку Syncthing/OneDrive.
Поскольку [Replication] общая для всех профилей, для разного поведения
проще два отдельных config.ini и два задания в планировщике.

config_docs.ini:
--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup_docs.log

[Replication]
enabled = true
marker_name = BACKUP_TARGET

[Include]
patterns = *.docx, *.xlsx, *.pdf

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

config_photos.ini:
--------------------------------------------------------------------------------
[General]
backup_base = C:\Users\user\OneDrive\backup
logging_enabled = true
log_file = C:\Users\user\OneDrive\backup\logs\backup_photos.log

[Replication]
enabled = false

[Include]
patterns = *.jpg, *.jpeg, *.png, *.heic

[Folders]
paths =
    C:\Users\user\Pictures
--------------------------------------------------------------------------------

Запуск:
    backup.exe -c config_docs.ini -y
    backup.exe -c config_photos.ini -y

(в планировщике — две задачи)

ПРИМЕР 15. Бэкап в облако через rclone (хук)
================================================================================
Когда: хотите, чтобы архивы автоматически уезжали в облако.

Требуется: rclone (https://rclone.org), настроенный remote:
    rclone config   (создать remote, например 'yandex')

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

# Команда-хук: shell раскроет %BACKUP_FILE% и т.д.
# ВАЖНО: кавычки вокруг %BACKUP_FILE% обязательны (путь может быть с пробелами)
post_backup_hook = rclone copy "%BACKUP_FILE%" "yandex:Backups/%BACKUP_PROFILE%/%BACKUP_TYPE%/"
post_hook_timeout = 1800

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

После каждого бэкапа архив уедет в Яндекс.Диск → Backups/<профиль>/<full|inc>/.

Проверка без бэкапа:
    backup.exe --test-hook

На Linux — то же, но с $BACKUP_FILE:
    post_backup_hook = rclone copy "$BACKUP_FILE" "yandex:Backups/$BACKUP_PROFILE/$BACKUP_TYPE/"


================================================================================
ПРИМЕР 16. Бэкап на SSH-сервер через rsync (хук)
================================================================================
Когда: есть свой сервер, хотите rsync (эффективнее scp).

Требуется: SSH-ключ без пароля:
    ssh-keygen && ssh-copy-id user@backup-server

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

# Вариант 1: готовая команда rsync (Linux / WSL / Git Bash)
post_backup_hook = rsync -az --timeout=600 "%BACKUP_FILE%" "user@backup-server:/srv/backup/%BACKUP_PROFILE%/%BACKUP_TYPE%/"
post_hook_timeout = 1200

# Вариант 2: путь к скрипту (upload_hook.sh / upload_hook.bat)
# post_backup_hook = C:\BackupTool\upload_hook.bat
# post_hook_timeout = 1200

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------


================================================================================
ПРИМЕР 17. Уведомление в Telegram (хук)
================================================================================
Когда: хотите получать сообщение после каждого бэкапа.

Требуется: бот в Telegram (@BotFather) → TOKEN; свой CHAT_ID
(узнать: https://api.telegram.org/bot<TOKEN>/getUpdates).

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
logging_enabled = true
log_file = E:\Backup\logs\backup.log

# Только уведомление (без отправки файла)
post_backup_hook = curl -s -X POST "https://api.telegram.org/bot123456:ABC-DEF/sendMessage" -d "chat_id=123456789" -d "text=Бэкап %BACKUP_PROFILE%/%BACKUP_TYPE% готов: %BACKUP_FILE% (%BACKUP_SIZE% байт)"
post_hook_timeout = 60

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Замените 123456:ABC-DEF на свой TOKEN, 123456789 — на свой CHAT_ID.
Одна строка, без пробелов внутри кавычек, кроме текста сообщения.

Если хотите ещё и файл (до 50 МБ — лимит Bot API), используйте скрипт
upload_hook.bat (там вариант D) — команда в одну строку получится слишком
длинной и хрупкой.

ПРИМЕР 18. Минимальный: только хук + локально
================================================================================
Когда: хотите проверить хук, не настраивая репликацию.

--------------------------------------------------------------------------------
[General]
backup_base = E:\Backup
post_backup_hook = C:\BackupTool\upload_hook.bat
post_hook_timeout = 600

[Replication]
enabled = false

[Folders]
paths =
    C:\Users\user\Documents
--------------------------------------------------------------------------------

Проверка:
    backup.exe --test-hook
    # 🧪 Тест хука — профиль 'default', архив: 2026-11-27_full.zip
    # 🪝 Хук-скрипт: C:\BackupTool\upload_hook.bat
    #   ✅ 2026-11-27_full.zip — готово


================================================================================
ПОДСКАЗКИ
================================================================================

1. backup_base — КОРНЕВАЯ папка. Внутри создаются подпапки по именам
   профилей. Не указывайте путь, который уже содержит имя профиля.

   Правильно:   backup_base = E:\Backup
   Результат:   E:\Backup\docs\full\..., E:\Backup\photos\full\...

   Неправильно: backup_base = E:\Backup\docs
   Результат:   E:\Backup\docs\docs\full\...

2. max_full_backups и max_incremental_backups — на КАЖДЫЙ профиль отдельно.
   2 профиля + max_full_backups = 4 → до 8 полных архивов.

3. max_age_days = 0 отключает удаление по возрасту. Архивы копятся, пока
   не упрутся в лимит по количеству (или в место на диске).

4. compression_level:
   0 — без сжатия (быстро, много места)
   6 — оптимально (по умолчанию)
   9 — максимум (медленно, мало места)

5. verify_archive = true — после создания архива проверяется целостность
   (testzip). Для важных данных оставьте true.

6. min_free_space — минимум свободного места на диске с backup_base.
   По умолчанию 1 ГБ.

7. Не храните пароль в открытом виде, если config.ini может попасть к другим.
   Используйте encryption_password_file = путь_к_файлу.

8. Если не уверены в настройках — запустите с --dry-run. Утилита покажет,
   сколько файлов найдено, куда будет сохранён архив, но ничего не создаст.

9. Для хука: если путь к скрипту/команде содержит пробелы — заключайте
   в кавычки. В командах (rclone, scp, curl) всегда заключайте
   %BACKUP_FILE% / $BACKUP_FILE в кавычки.

10. При использовании --add-profile утилита пишет в секцию [Profile:ИМЯ],
    а [Include] / [Exclude] остаются глобальными. Если нужны разные фильтры
    для профилей — правьте config.ini вручную (или используйте два config.ini
    с -c, см. пример 14).

================================================================================
ПРО ПУТИ: WINDOWS И LINUX
================================================================================

Во всех примерах пути указаны в стиле Windows (C:\Users\user\...).
Если вы работаете на Linux или macOS — замените их на свои:

  Windows                              Linux / macOS
  ----------------------------------   ------------------------------------
  C:\Users\user\Documents              /home/user/Documents
  C:\Users\user\Desktop                /home/user/Desktop
  C:\Users\user\Pictures               /home/user/Pictures
  C:\Users\user\Projects               /home/user/Projects
  C:\Users\user\Videos                 /home/user/Videos
  C:\BackupTool\                       /home/user/backup_tool/
  E:\Backup                            /mnt/backup   (или /home/user/backups)
  E:\Backup\logs\backup.log            /home/user/backups/logs/backup.log
  I:\                                  /media/user/USB
  J:\                                  /media/user/HDD
  \\NAS\backup\MyPC                    /mnt/nas/backup/MyPC

Кроме путей, на Linux меняются:

  • Имя бинарника:   backup.exe   →   ./backup
  • Хук-скрипт:      upload_hook.bat   →   upload_hook.sh
  • Хук (команда):   %BACKUP_FILE%   →   $BACKUP_FILE
  • Слэши в путях:   \   →   /

Пример: config.ini из Примера 1 для Linux будет выглядеть так:

--------------------------------------------------------------------------------
[General]
backup_base = /home/user/backups
logging_enabled = true
log_file = /home/user/backups/logs/backup.log

[Replication]
enabled = false

[Folders]
paths =
    /home/user/Documents
--------------------------------------------------------------------------------

Всё остальное (ключи, значения, структура секций) — одинаково на Windows
и Linux.
