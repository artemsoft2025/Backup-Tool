1. ОБЩЕЕ ОПИСАНИЕ
================================================================

Backup Tool — инструмент для автоматического резервного копирования
файлов с поддержкой:

  🗓️  Умное расписание — полный бэкап по расписанию с порогом изменений
  📦  Инкрементальные бэкапы — только изменённые файлы
  🗃️  Разделение на тома — автоматическое разбиение больших архивов
  🔐  Шифрование AES-256 — защита конфиденциальных данных
  📝  Логирование — все действия записываются в файл с ротацией
  🧪  Dry-run режим — тестовый прогон без создания файлов
  🎯  Профили — разные настройки для разных типов данных
  🔍  Контрольные суммы — точное определение изменений
  ♻️  Восстановление — из архива или цепочки томов (--restore)


================================================================
2. УСТАНОВКА
================================================================

Linux / macOS:
  1. Распакуйте архив с программой в любую папку
  2. Сделайте файл исполняемым:
       chmod +x backup
  3. (Опционально) скопируйте в удобное место:
       sudo cp backup /usr/local/bin/

Windows:
  1. Распакуйте архив с программой в любую папку
  2. Запускайте backup.exe (двойной клик или из cmd/PowerShell)

Проверка установки:
  ./backup --help


================================================================
3. БЫСТРЫЙ СТАРТ
================================================================

Шаг 1: Создать конфиг
  ./backup --init-config

Шаг 2: Отредактировать конфиг
  nano config.ini      (Linux/macOS)
  notepad config.ini   (Windows)
  # Указать папки для бэкапа в секции [Folders]

Шаг 3: Проверить, что будет сделано (ничего не пишет на диск)
  ./backup --dry-run

Шаг 4: Запустить бэкап
  ./backup

Готово! 🚀


================================================================
4. КОМАНДЫ И ПАРАМЕТРЫ
================================================================

Команда                                      Описание
-------------------------------------------  ----------------------------------------
./backup                                     Бэкап всех профилей
./backup -p NAME                             Бэкап конкретного профиля
./backup --dry-run                           Тестовый прогон (ничего не создаёт)
./backup --list                              Список созданных бэкапов
./backup --stats                             Статистика (размер, свободное место)
./backup --init-config                       Создать пример конфигурации
./backup -c FILE                             Использовать другой файл конфига
./backup -y                                  Неинтерактивный режим (все ответы "да")
./backup --restore ARCH --target D           Восстановить архив в папку D
./backup --add-profile NAME --paths DIR      Добавить новый профиль

Параметры добавления профиля:
  --add-profile NAME          Имя нового профиля
  --paths DIR1 DIR2 ...       Папки для бэкапа
  --include "*.py" "*.txt"    Белый список (опционально)
  --exclude "*.tmp" "*.log"   Чёрный список (опционально)

5. КОНФИГУРАЦИЯ

5.1 ОСНОВНЫЕ НАСТРОЙКИ
----------------------------------------------------------------

[General]
backup_base = ~/backups           # базовая папка для хранения
max_full_backups = 4              # сколько полных хранить
max_incremental_backups = 7       # сколько инкрементальных хранить
max_age_days = 180                # удалять бэкапы старше N дней (0 = бессрочно)
verify_archive = true             # проверять целостность после создания
show_progress = true              # показывать прогресс-бар
debug = false                     # подробный вывод
hash_size = 1048576               # размер для контрольной суммы (1 MB)
max_file_size = 0                 # макс. размер файла (0 = без ограничений)
min_free_space = 1073741824       # минимум свободного места (1 GB)
skip_large_files = false          # true = пропускать большие, false = предупреждать
compression_level = 6             # 0-9 (6 — оптимум)
threads = 4                       # потоков для сжатия
max_inc_files = 0                 # порог изменений (см. 5.2)

5.2 РАСПИСАНИЕ
----------------------------------------------------------------

[Schedule]
schedule_mode = smart             # weekly | monthly | smart
full_backup_day = 1               # день недели (1=пн ... 7=вс)
full_backup_day_of_month = 1      # день месяца (1-31, 0 = последний)

Режимы:
  weekly   — по указанному дню недели полный (если изменений >= порога)
  monthly  — в указанный день месяца полный (если изменений >= порога)
  smart    — по понедельникам полный при накоплении изменений;
             плюс принудительный полный, если полного нет
             или прошло >= 30 дней с последнего полного

ПОРОГ ИЗМЕНЕНИЙ (max_inc_files):
  Управляет тем, сколько изменений нужно накопить, чтобы в день
  расписания сделать ПОЛНЫЙ бэкап вместо инкрементального.

    max_inc_files = 0   → полный при ЛЮБОМ изменении (1 и больше)
    max_inc_files = 50  → полный только если изменений >= 50,
                          иначе инкремент
    max_inc_files = 500 → полный только при 500+ изменениях

  Это же значение используется как аварийный переключатель:
  если в ЛЮБОЙ день изменений больше max_inc_files — делается
  полный бэкап, а не инкремент.

ПРИМЕРЫ ПОВЕДЕНИЯ (все при schedule_mode = smart, full_backup_day = 1):

  Понедельник, 0 изменений, есть полный:
    → инкремент "Нет изменений" (ничего не создаётся)

  Понедельник, 1 изменение, max_inc_files = 0:
    → полный (порог = 1)

  Понедельник, 1 изменение, max_inc_files = 50:
    → инкремент (1 < 50)

  Понедельник, 100 изменений, max_inc_files = 50:
    → полный (100 >= 50)

  Среда, 100 изменений, max_inc_files = 50:
    → полный (аварийный переключатель, не день расписания)

  Любой день, прошло >= 30 дней с последнего полного:
    → полный (независимо от изменений)

  Любой день, полного нет:
    → полный

5.3 ФИЛЬТРЫ
----------------------------------------------------------------

[Include]
# Белый список — бэкапим ТОЛЬКО эти файлы.
# Если пусто — бэкапим всё (кроме исключённого).
patterns =
    *.txt
    *.docx
    *.xlsx
    *.pdf
    *.jpg
    *.png

[Exclude]
# Чёрный список — исключаем эти файлы (даже если в белом списке).
patterns =
    *.tmp
    *.log
    *.cache
    __pycache__
    .git
    *.bak
    Thumbs.db
    .DS_Store
    node_modules
    .venv
    venv

5.4 ШИФРОВАНИЕ
----------------------------------------------------------------

[General]
encryption_enabled = true
encryption_password = MyStrongPassword123!
# или безопаснее:
encryption_password_file = ~/.backup_password

Создание файла с паролем (Linux/macOS):
  echo "MyStrongPassword123!" > ~/.backup_password
  chmod 600 ~/.backup_password

Шифрование AES-256 встроено в программу — дополнительных
библиотек устанавливать не нужно.

5.5 ЛОГИРОВАНИЕ
----------------------------------------------------------------

[General]
logging_enabled = true
log_file = ~/logs/backup.log
log_level = INFO                  # DEBUG | INFO | WARNING | ERROR
log_max_size = 10485760           # 10 MB
log_backup_count = 3              # сколько старых логов хранить

5.6 РАЗДЕЛЕНИЕ НА ТОМА
----------------------------------------------------------------

[General]
max_volume_size = 2147483648      # 2 GB (0 = без разделения)
volume_prefix = part

Пример:
  Вместо одного файла 5 GB получаем:
    2026-07-30_full.part001.zip  (2 GB)
    2026-07-30_full.part002.zip  (2 GB)
    2026-07-30_full.part003.zip  (1 GB)

Восстановление из томов:
  ./backup --restore /path/to/2026-07-30_full.part001.zip --target /restore
  # Склеит все тома автоматически

6. ПРОФИЛИ
================================================================

Профили позволяют настроить разные типы бэкапов.

[Profile:NAME]
paths =
    ~/folder1
    ~/folder2
include =
    *.ext1
    *.ext2
exclude =
    *.tmp
    *.log
# Опционально (переопределяют глобальные):
max_file_size = 52428800
encryption_enabled = true
encryption_password = secret

Если профилей нет, но есть секция [Folders] — используется профиль
"default".

8. АВТОМАТИЗАЦИЯ
================================================================

8.1 Linux / macOS (cron)
----------------------------------------------------------------
  crontab -e

✅ Правильная запись:

  0 23 * * * cd /home/ПОЛЬЗОВАТЕЛЬ/project/backup_tool && /полный/путь/backup -p default >> /home/ПОЛЬЗОВАТЕЛЬ/logs/cron_backup.log 2>&1

ВАЖНО: Всегда используйте cd для перехода в папку с программой
и конфигом, иначе backup не найдёт config.ini.

8.2 Windows (Планировщик задач)
----------------------------------------------------------------
  schtasks /create /tn "Backup" ^
    /tr "C:\путь\backup.exe -p default" ^
    /sc daily /st 23:00

Или через графический «Планировщик заданий»:
  • Действие: запуск программы C:\путь\backup.exe
  • Аргументы: -p default
  • Рабочая папка: C:\путь\

8.3 Типовые ошибки
----------------------------------------------------------------
  ❌ "Конфиг не найден: config.ini"
     → добавьте cd /path/to/folder && перед командой
     → или укажите -c /path/to/config.ini

  ❌ Permission denied (Linux/macOS)
     → chmod +x backup

  ❌ Лог не создаётся
     → mkdir -p ~/logs

8.4 Проверка работы cron
----------------------------------------------------------------
Шаг 1: тестовая задача каждую минуту
  * * * * * cd /path/to/folder && /полный/путь/backup --dry-run -p default >> ~/logs/cron_test.log 2>&1

Шаг 2: смотрим лог
  tail -f ~/logs/cron_test.log

Шаг 3: удаляем тестовую задачу

8.5 Готовые примеры
----------------------------------------------------------------
# Ежедневный бэкап в 23:00
0 23 * * * cd /home/USER/backup_tool && /home/USER/backup_tool/backup -p default >> /home/USER/logs/cron_backup.log 2>&1

# Разные профили в разное время
0 22 * * * cd /home/USER/backup_tool && ./backup -p documents >> /home/USER/logs/cron_docs.log 2>&1
0 23 * * * cd /home/USER/backup_tool && ./backup -p photos >> /home/USER/logs/cron_photos.log 2>&1

# С явным указанием конфига
0 23 * * * /home/USER/backup_tool/backup -c /home/USER/backup_tool/config.ini -p default >> /home/USER/logs/cron.log 2>&1

8.6 Диагностика
----------------------------------------------------------------
  # 1. Проверить, что программа работает вручную
  cd /path/to/folder && ./backup --dry-run -p default

  # 2. Проверить задачи cron
  crontab -l

  # 3. Системный лог cron
  sudo journalctl -u cron -f
  # или
  sudo tail -f /var/log/syslog | grep CRON

8.7 Важные замечания
----------------------------------------------------------------
  • Пути должны быть абсолютными
  • Обязательно перенаправляйте вывод (>> log 2>&1)
  • cron не загружает .bashrc — задавайте PATH явно
  • Убедитесь в правах на чтение/запись

9. ЧАСТО ЗАДАВАЕМЫЕ ВОПРОСЫ
================================================================

❓ Почему в понедельник бэкап не полный, хотя раньше был?

  С v5.3 полный в день расписания делается только если накоплено
  достаточно изменений. Порог задаётся max_inc_files.

  Если хотите прежнее поведение (полный при любом изменении):
    max_inc_files = 0

  Если хотите порог:
    max_inc_files = 50

❓ Почему в понедельник полный бэкап 68 MB ради одного файла?

  У вас max_inc_files = 0 → порог = 1 → любое изменение триггерит
  полный. Поставьте max_inc_files = 50 (или другое), чтобы полный
  делался только при накоплении.

❓ Почему бэкап не запускается из cron?

  Причина: программа не находит config.ini, потому что cron запускает
  её из ~/.

  Решение:
    cd /path/to/folder && ./backup -p default
  или
    /path/to/backup -c /path/to/config.ini -p default

❓ Как восстановить файлы?

  Полный архив:
    ./backup --restore backups/full/2026-07-30_full.zip --target /restore

  Из томов:
    ./backup --restore backups/full/2026-07-30_full.part001.zip --target /restore
    (склеит все тома автоматически)

  Вручную (незашифрованный):
    unzip backup.zip -d /restore/folder

  Вручную (зашифрованный):
    используйте встроенную команду --restore (см. выше) —
    она сама подберёт пароль из профиля

❓ Как восстановить состояние на определённую дату?

  Инкрементальный бэкап содержит только ИЗМЕНЁННЫЕ файлы.
  Чтобы восстановить состояние на дату D:
    1. Распакуйте полный бэкап, созданный до D
    2. Поверх распакуйте все инкременты в хронологическом порядке,
       созданные между полным и D

  Пример:
    ./backup --restore full/2026-07-01_full.zip --target /restore
    ./backup --restore inc/2026-07-05_inc_230000_000001.zip --target /restore
    ./backup --restore inc/2026-07-10_inc_230000_000002.zip --target /restore

❓ Можно ли делать бэкап на сетевой диск?

  Да:
    backup_base = /mnt/network_drive/backups

❓ Что делать при "недостаточно места"?

  • Уменьшить max_full_backups
  • Уменьшить max_age_days
  • Увеличить compression_level (до 9)
  • Задать max_file_size для исключения больших файлов

❓ Как посмотреть логи?

  cat ~/logs/backup.log
  tail -f ~/logs/backup.log

10. УСТРАНЕНИЕ НЕПОЛАДОК
================================================================

Ошибка: "Нет полного бэкапа"
  → Программа сама создаст полный при первом запуске.

Ошибка: "Недостаточно свободного места"
  → df -h ~/backups
  → уменьшить max_full_backups / max_age_days
  → или вручную: rm -rf ~/backups/full/2026-01-*

Ошибка: "Папка не найдена"
  → Проверьте пути в конфиге [Folders]

Ошибка: "Permission denied" на отдельном файле
  → Файл занят другой программой (например, открыт в Word).
  → С v5.3 такой файл НЕ попадает в кэш как сохранённый и будет
    повторён в следующем запуске. Закройте программу — и файл
    успешно сохранится.

Бэкап не создаётся в указанную папку
  → chmod 755 ~/backups


================================================================
11. ЧТО НОВОГО В v5.3
================================================================

По сравнению с v5.1:

  🆕 ПОРОГ ИЗМЕНЕНИЙ ДЛЯ ПОЛНОГО БЭКАПА
     max_inc_files теперь управляет не только аварийным переключением,
     но и порогом в день расписания:
       max_inc_files = 0  → полный при любом изменении (как раньше)
       max_inc_files = 50 → полный только при 50+ изменениях

  🆕 ФИКС КЭША ПРИ ОШИБКАХ ЧТЕНИЯ
     Если файл не удалось прочитать (Permission denied и т.п.),
     он НЕ считается сохранённым и будет повторён в следующем запуске.
     Раньше кэш "врал", что файл сохранён, и на следующем запуске
     появлялось фантомное "1 изменение".

  🆕 СОРТИРОВКА В СТАТИСТИКЕ
     Бэкапы в --stats и --list теперь отсортированы по дате (новые сверху).

  🆕 ВОССТАНОВЛЕНИЕ ИЗ ТОМОВ
     --restore автоматически склеивает все тома с общим префиксом.

  🆕 НЕИНТЕРАКТИВНЫЙ РЕЖИМ
     Флаг -y / --yes — отвечать "да" на все вопросы.

  🆕 ВЕРИФИКАЦИЯ ТОМОВ
     При verify_archive = true тома склеиваются во временный файл
     и проверяются целиком (а не только первый том).
