## 1. Что это

**Backup Tool** — консольная утилита для резервного копирования файлов.

Умеет:

- делать полные и инкрементальные (только изменения) бэкапы;
- хранить несколько профилей (например, «документы» и «фото» отдельно);
- сжимать в ZIP и при желании шифровать (AES-256);
- разбивать большие архивы на тома;
- автоматически копировать архивы на флешку или внешний диск, на котором лежит файл-метка `BACKUP_TARGET` (защита от записи на чужие носители);
- восстанавливать файлы из архива;
- работать по расписанию (через планировщик задач ОС).

Работает на **Windows** и **Linux**. Один исполняемый файл, без установки.

## 2. Что нового в v5.4

- Репликация архивов на носители с файлом-меткой `BACKUP_TARGET`.
- Команды `--init-target` и `--list-targets`.
- Команда `--replicate` — догнать отсутствующие архивы на носители.
- Каждый профиль хранится в своей подпапке: `<backup_base>/<профиль>/` (профили больше не пересекаются).
- Размеры файлов в статистике показываются в удобных единицах (B, KB, MB, GB).
- Вызывать внешний скрипт или команду после каждого успешно созданного архива. Это позволяет автоматически загружать архив в облако, на SSH-сервер бэкапов или отправлять уведомление — без правки самого `backup`. Подробности в файле `HOOK_README.txt`.

## 3. Быстрый старт (5 минут)

**Шаг 1.** Положите исполняемый файл в отдельную папку, например:

```
Windows:  C:\BackupTool\
Linux:    ~/backup_tool/
```

**Шаг 2.** Откройте командную строку (терминал) в этой папке.

**Шаг 3.** Создайте файл конфигурации:

```bash
backup.exe --init-config          # Windows
./backup --init-config            # Linux
```

Рядом появится `config.ini` — откройте его блокнотом и укажите:

- `backup_base` — куда складывать бэкапы (например, `E:\Backup`);
- пути к папкам, которые нужно бэкапить (секция `[Folders]`).

**Шаг 4.** Проверьте, что всё настроено верно:

```bash
backup.exe --dry-run
```

Утилита покажет, сколько файлов найдено и куда будет сохранён архив, но ничего не создаст.

**Шаг 5.** Запустите бэкап:

```bash
backup.exe
```

Готово. Архивы появятся в `<backup_base>/<профиль>/full/` и `/inc/`.

**Шаг 6 (необязательно).** Подключите флешку и настройте репликацию — см. раздел [8](#8-репликация-на-флешку--внешний-диск).

## 4. Файлы и папки

После первого запуска рядом с программой и в папке `backup_base` появятся:

```
config.ini                      — настройки (создаётся командой --init-config)
<backup_base>/
  <профиль>/
    full/                       — полные бэкапы (YYYY-MM-DD_full.zip)
    inc/                        — инкрементальные бэкапы (YYYY-MM-DD_inc_...zip)
    .cache/                     — служебный кэш (не трогать)
```

На носителе с меткой (флешка / внешний диск):

```
BACKUP_TARGET                   — файл-метка (создаётся командой --init-target)
BackupTool/
  <профиль>/
    full/
    inc/
```

Логи (если включено логирование):

```
Windows:  %USERPROFILE%\logs\backup.log
Linux:    ~/logs/backup.log
```

## 5. Команды

| Команда | Описание |
| --- | --- |
| `backup` | Бэкап всех профилей |
| `backup -p ИМЯ` | Бэкап одного профиля |
| `backup --dry-run` | Тестовый прогон (ничего не создаётся) |
| `backup --list` | Список существующих архивов |
| `backup --stats` | Статистика (то же, что `--list`) |
| `backup --init-config` | Создать `config.ini` (если его ещё нет) |
| `backup --add-profile ИМЯ --paths "C:\Docs" "D:\Work"` | Добавить новый профиль в `config.ini` |
| `backup --init-target I:\` | Создать файл-метку `BACKUP_TARGET` на носителе |
| `backup --list-targets` | Показать найденные носители с меткой |
| `backup --replicate` | Догнать отсутствующие архивы на носители |
| `backup --replicate -p ИМЯ` | То же для одного профиля |
| `backup --replicate --dry-run` | Показать, что будет скопировано |
| `backup --restore <архив> --target <папка>` | Восстановить архив в указанную папку |
| `backup --help` | Краткая справка по всем командам |

**Флаги:**

| Флаг | Описание |
| --- | --- |
| `-c`, `--config ФАЙЛ` | Указать другой `config.ini` |
| `-p`, `--profile ИМЯ` | Выбрать профиль |
| `-y`, `--yes` | Отвечать «да» на все вопросы (для скриптов) |

## 6. Настройка (config.ini)

Файл `config.ini` состоит из секций:

| Секция | Назначение |
| --- | --- |
| `[General]` | Общие параметры (пути, лимиты, сжатие, шифрование) |
| `[Replication]` | Репликация на носители с меткой |
| `[Schedule]` | Когда делать полный бэкап |
| `[Include]` | Какие файлы включать (белый список) |
| `[Exclude]` | Какие файлы исключать (чёрный список) |
| `[Profile:ИМЯ]` | Пути для конкретного профиля |

### Ключевые параметры `[General]`

| Параметр | Описание |
| --- | --- |
| `backup_base` | Куда складывать архивы. Пример: `E:\Backup` |
| `max_full_backups` | Сколько полных бэкапов хранить (на профиль) |
| `max_incremental_backups` | Сколько инкрементальных хранить (на профиль) |
| `max_age_days` | Удалять архивы старше N дней (0 — не удалять) |
| `verify_archive` | Проверять целостность архива после создания |
| `compression_level` | Сжатие 0–9 (6 — оптимально) |
| `min_free_space` | Минимум свободного места на диске (в байтах) |
| `encryption_enabled` | Включить шифрование AES-256 (нужен `pyzipper`*) |
| `encryption_password` | Пароль шифрования |

> **\* Примечание:** для шифрования требуется установленный пакет `pyzipper`. Если его нет — шифрование автоматически отключается с предупреждением.

### Параметры `[Schedule]`

| Параметр | Описание |
| --- | --- |
| `schedule_mode` | `weekly` \| `monthly` \| `smart` |
| `full_backup_day` | День недели для полного (1=пн … 7=вс) |
| `full_backup_day_of_month` | День месяца для полного (1–31) |

**Режимы:**

- `weekly` — полный по указанному дню недели, если есть изменения;
- `monthly` — полный по указанному дню месяца, если есть изменения;
- `smart` — полный раз в 30 дней + по дню недели, если есть изменения.

Параметры `[Replication]` — см. раздел [8](#8-репликация-на-флешку--внешний-диск).

## 7. Профили

**Профиль** — это отдельный набор папок для бэкапа. Например:

```ini
[Profile:docs]
paths =
    C:\Users\user\Documents
    C:\Users\user\Desktop

[Profile:photos]
paths =
    C:\Users\user\Pictures
```

Каждый профиль хранится в своей подпапке:

```
E:\Backup\docs\full\...
E:\Backup\photos\full\...
```

Лимиты `max_full_backups` / `max_incremental_backups` действуют на **каждый профиль отдельно**. То есть при `max_full_backups = 4` у `docs` будет до 4 полных архивов и у `photos` — до 4 полных.

Если в `config.ini` нет ни одного `[Profile:*]`, но есть секция `[Folders]` — создаётся один профиль с именем `default`.

## 8. Репликация на флешку / внешний диск

**Зачем:** чтобы резервные копии лежали не только на одном диске. Если диск сломается — останется копия на флешке (и наоборот).

**Как это работает:**

- Утилита ищет подключённые носители (флешки, внешние HDD).
- На каждом носителе проверяет наличие файла-метки `BACKUP_TARGET` в корне.
- Если метка есть — копирует архив на этот носитель.
- Если метки нет — носитель игнорируется (защита от записи на чужую флешку).

### Шаг 1. Включить репликацию в config.ini

```ini
[Replication]
enabled = true
marker_name = BACKUP_TARGET
```

### Шаг 2. Создать метку на носителе

```bash
backup --init-target I:\
```

где `I:\` — буква вашей флешки; на Linux, например, `/media/user/USB`.

На носителе появится файл `BACKUP_TARGET` с содержимым:

```
# Backup Tool target marker
# Этот носитель разрешён для резервных копий.
id=USB
```

### Шаг 3. Проверить, что утилита видит носитель

```bash
backup --list-targets
```

Пример вывода:

```
📤 Найдено носителей с меткой: 1
  • USB  I:\  свободно: 36.4 GB
```

### Шаг 4. Обычный бэкап теперь будет копировать архивы и на носитель

```bash
backup
```

В логе появится:

```
📤 Репликация на 1 носител(ь/я/ей)...
  ✅ Скопировано на USB: 2026-11-25_full.zip
```

### Догон вручную (`--replicate`)

Если бэкап был сделан без подключённой флешки, архивы на неё не попали. Подключите флешку и выполните:

```bash
backup --replicate
```

Утилита скопирует всё, чего на носителе ещё нет. Повторный запуск ничего не сделает (проверка по имени и размеру).

Проверить, что будет скопировано, без реального копирования:

```bash
backup --replicate --dry-run
```

### Важно

- Репликация — это **копирование**. Локальные архивы не удаляются.
- Носители без метки `BACKUP_TARGET` не трогаются вообще.
- Если на носителе уже есть архив с тем же именем и размером — он пропускается. Если размер не совпал — перезаписывается.
- Если на носителе мало места — копирование пропускается с предупреждением, бэкап при этом считается успешным (локальная копия есть).

## 9. Восстановление

Восстановить один архив в указанную папку:

```bash
backup --restore E:\Backup\docs\full\2026-11-25_full.zip --target C:\Restore
```

Если архив зашифрован — утилита попробует пароль из `config.ini` (секция `[General]`, параметр `encryption_password` или `encryption_password_file`).

Если архив разбит на тома (файлы `.part001.zip`, `.part002.zip`, ...) — достаточно указать первый том, остальные будут найдены автоматически:

```bash
backup --restore E:\Backup\docs\full\2026-11-25_full.part001.zip --target C:\Restore
```

### Важно про инкрементальные архивы

Инкрементальный архив содержит **только** изменения с момента предыдущего бэкапа. Чтобы получить полное состояние на дату, нужно восстановить:

1. последний полный архив (`full/YYYY-MM-DD_full.zip`), затем
2. все инкрементальные архивы (`inc/*.zip`) по порядку дат — от старых к новым.

Порядок важен: каждый инкремент накладывается поверх предыдущего.

## 10. Расписание (планировщик)

### Windows (Планировщик заданий)

1. Откройте «Планировщик заданий» → «Создать задачу».
2. Триггер: «Ежедневно», время — например, `23:00`.
3. Действие: «Запуск программы».

   | Поле | Значение |
   | --- | --- |
   | Программа | `C:\BackupTool\backup.exe` |
   | Аргументы | `-y` |
   | Рабочая папка | `C:\BackupTool\` |

4. Сохраните.

### Linux (cron)

Откройте `crontab -e` и добавьте строку (запуск каждый день в 23:00):

```cron
0 23 * * * cd /home/user/backup_tool && ./backup -y >> /home/user/logs/cron.log 2>&1
```

Флаг `-y` (`--yes`) нужен, чтобы утилита не задавала вопросов в неинтерактивном режиме (например, при нехватке места).

## 11. Частые вопросы (FAQ)

**В: Где хранятся мои бэкапы?**
О: В папке, указанной в `config.ini` как `backup_base`. Внутри — подпапки по именам профилей (`docs`, `photos` и т.д.).

**В: Что будет, если я удалю `config.ini`?**
О: Утилита не запустится. Создайте заново командой `--init-config`. Кэш и архивы не пострадают, но настройки (пути, лимиты) придётся указать заново.

**В: Можно ли бэкапить на сетевой диск (NAS)?**
О: Да. Укажите путь в `backup_base`, например `\\NAS\backup` или `/mnt/nas/backup`. Убедитесь, что у учётной записи есть права на запись.

**В: Что такое «полный» и «инкрементальный» бэкап?**
О: Полный — все файлы целиком. Инкрементальный — только те, что изменились с момента предыдущего бэкапа. Инкременты меньше, но для восстановления нужен полный + все инкременты по порядку.

**В: У меня включено шифрование, но архив не открывается.**
О: Проверьте пароль в `config.ini`. Если пароль утерян — восстановить архив невозможно (AES-256 без бэкдора).

**В: Флешка не определяется как носитель с меткой.**
О: Проверьте:

1. файл `BACKUP_TARGET` лежит в **корне** флешки (не в подпапке);
2. в файле есть строка `id=...` (без пробелов вокруг `=`);
3. флешка не смонтирована только для чтения.

Запустите `--list-targets` — утилита покажет, что нашла.

**В: `--replicate` пишет «Носителей с меткой не найдено».**
О: Флешка не подключена, или на ней нет файла `BACKUP_TARGET`, или она не в списке стандартных точек монтирования. Создайте метку: `--init-target I:\`.

## 12. Решение проблем

### СИМПТОМ: «Конфиг не найден: config.ini»

- **Причина:** утилита запущена не из той папки, где лежит `config.ini`.
- **Решение:** либо перейдите в папку с `config.ini`, либо укажите путь явно:

```bash
backup -c C:\BackupTool\config.ini
```

### СИМПТОМ: «Недостаточно свободного места!»

- **Причина:** на диске с `backup_base` меньше `min_free_space` байт.
- **Решение:** освободите место, уменьшите `min_free_space` в `config.ini`, или перенесите `backup_base` на другой диск.

### СИМПТОМ: бэкап идёт, но файлы не попадают в архив

- **Причина:** сработали фильтры Include/Exclude, или файл занят другой программой (Windows), или нет прав на чтение (Linux).
- **Решение:** проверьте секции `[Include]` и `[Exclude]` в `config.ini`. Для диагностики запустите с флагом `--dry-run` — он покажет, сколько файлов найдено.

### СИМПТОМ: репликация не копирует на флешку

- **Причина:** `[Replication] enabled = false`, или нет файла `BACKUP_TARGET`, или на флешке мало места.
- **Решение:** проверьте `config.ini`, запустите `--list-targets`, проверьте свободное место на флешке.

### СИМПТОМ: «pyzipper не установлен, шифрование отключено»

- **Причина:** включено `encryption_enabled = true`, но пакет `pyzipper` отсутствует.
- **Решение:** либо установите `pyzipper`, либо отключите шифрование (`encryption_enabled = false`).

### Логи

Подробный лог пишется в файл, указанный в `config.ini` (`log_file`). Если что-то идёт не так — загляните туда, там больше деталей, чем в консоли. Для ещё более подробного вывода включите в `config.ini`:

```ini
debug = true
```
